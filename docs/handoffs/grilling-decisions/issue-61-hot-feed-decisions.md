## 1. 用户定案（grilling 2026-08-25，AskUserQuestion）

### D1 热度公式 = 7 天窗口 + 赞×1 + 评论×3，降序

- **问题**: 热度怎么算？信号源、时间窗口、权重？
- **选项**: A 7 天窗口 + 赞×1+评论×3；B 全时间 + 时间衰减（HN 式）；C 24h 快热。
- **决定**: **A**。
- **理由**: 简单、可解释、评论比赞更值钱；衰减公式复杂，24h 窗口过度强调当下。
- **语义钉死（F3 补充）**: 「7 天窗口」= 帖子创建时间 `created_at ∈ [now-7d, now]`；计数 = 该帖**全生命周期**赞/评论总数。不是「近 7 天互动热度」。

### D2 入口形态 = 首页三分段「全部 / 热门 / 关注」，热门公开

- **问题**: 热门入口放哪里？
- **选项**: A 首页 SegTabs 三分段；B 单独入口/徽标。
- **决定**: **A**。
- **理由**: 贴合现有首页分段 IA；热门是全局公开内容，游客也可见（`/posts` 在 reads 组，OptionalAuth）。

### D3 置顶/精华关系 = 置顶恒顶，不做精华分段

- **问题**: 置顶帖在热门里怎么排？精华要不要单独段？
- **选项**: A 置顶恒顶 + 不做精华段；B 置顶恒顶 + 加精华段；C 热门纯热度不看置顶。
- **决定**: **A**。
- **理由**: 与全部流置顶行为一致；范围最小，精华帖按热度自然参与。
- **评审裁决补充（F2）**: **窗口优先**。`is_pinned` 仅作为结果集内排序首键，不做窗口豁免；超窗置顶帖从热门段不出现，窗口内置顶帖恒顶。

## 2. 架构既定（非开放，照做）

- **热度排序必须在 SQL 现算**：赞/评论数不落库（`postViews` 现场 Count），为保证分页正确，排序 + offset/limit 必须在同一查询完成（§6.1 设计裁决）。
- **复用既有 query 路径**：`tab=hot` 与 `board_id`/`topic_id`/`author_id`/`tag` 过滤正交叠加（§6.3 设计裁决）。
- **测试纪律**：service 单测跨 fake repo seam，fake 镜像 repo 语义（含 hot 窗口/权重/置顶）；SQL 正确性由 handler 集成测试（testcontainers 真 PG）兜底（§6.4 设计裁决）。
